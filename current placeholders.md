# Current Placeholders and Integration Register

**Last reviewed:** July 23, 2026
**Scope:** active DaaS application only. The old employee codebase and deferred integrations are excluded.

This is the living handoff list for temporary values, mocks, external accounts, and company-owned decisions. It is not a list of features that are safe for production. Production gates are tracked in `production hardening.md`.

## Maintenance rule

- Update this file whenever code adds, changes, or resolves a placeholder.
- Record the active code location, safe current behavior, missing input, and owner.
- Never paste a password, authentication/recovery secret, provider token, API key, reset code, or merchant credential here, in source code, or in chat.
- Move resolved items to the resolved table; preserve historical implementation changes in `history_of_changes.md`.

## Review checklist before launch

1. Every active row is resolved or explicitly accepted with an accountable owner.
2. `production hardening.md` release blockers have evidence, not assumptions.
3. Secrets exist only in a local/deployment secret store and have been rotated if ever exposed.
4. External integrations have passed sandbox and failure-path tests.
5. File/line references are refreshed after final implementation changes.
